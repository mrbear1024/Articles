# 模块 8：脚本写作——口播感与节奏

> 写出来的文字和说出来的文字，是两种完全不同的东西。
> 大多数 AI 生成的脚本一念就知道"不对劲"——因为模型是在书面语上训练的。
> 本模块教你怎么让脚本"说起来像人话"。

---

## 8.1 口播脚本 vs 写作的根本差异

### 差异 1：节奏单位不同

- **写作的节奏单位**：句子和段落——读者自己控制速度。
- **口播的节奏单位**：呼吸和停顿——观众被你的速度推着走。

**实操**：写脚本时，在每个你需要换气的地方打一个 `/`。如果连续超过 30 个字没有 `/`，那句子太长了——拆。

### 差异 2：听觉不能"回看"

- **读文字**：看不懂可以回头重读。
- **听口播**：错过了就错过了——除非观众拖进度条（但他们不会）。

**实操**：每个关键概念，至少用两种方式表达一次。

```
❌ "这就是所谓的认知偏误中的锚定效应。"
✅ "这就是锚定效应——/ 你看到的第一个数字，/ 会影响你对后面所有数字的判断。"
```

### 差异 3："你"字要多

- **文章**可以用"我们"、"人们"、被动语态。
- **口播**必须用"你"——每 30 秒至少一次"你"。

```
❌ "研究表明，人们在做决策时往往受到第一印象的影响。"
✅ "你有没有发现——/ 你看到的第一个价格，/ 会影响你觉得后面的东西贵不贵？"
```

### 差异 4：耳朵听不到标点

- **书面**靠标点制造节奏：句号、逗号、破折号。
- **口播**靠三样东西制造节奏：

1. **停顿**：比任何词都有力量。`[停 1 秒]`
2. **重复**：同一个词说两遍 = 强调。"这很重要。/ 非常重要。"
3. **语气词**：适度使用。"对吧？""你想想看。""关键来了——"

## 8.2 口播脚本的四种结构模板

### 模板 1：HPAR（Hook-Promise-Action-Reward）

最通用的短视频结构：

```
Hook（0-5 秒）：让人停下来
"90% 的人不知道，他们用 AI 写的东西一看就能看出来。"

Promise（5-15 秒）：告诉他会得到什么
"今天我教你一个方法，/ 让 AI 写出来的东西，/ 读起来像你自己写的。"

Action（15 秒 - 结尾前 15 秒）：给出内容
[核心内容，分 3-5 个要点]

Reward（最后 10-15 秒）：可带走的总结 + 情绪价值
"记住这一条就够了：/ AI 是初稿机器，/ 你是改稿机器。/ 一个负责快，一个负责好。"
```

### 模板 2：问题 - 错误 - 正确

适合"纠正性"内容：

```
问题（0-10 秒）：指出一个常见痛点
"你是不是花了很多时间写推文，但互动寥寥无几？"

错误做法（10-40 秒）：指出大家在做的错事
"大多数人犯了三个错误——"
[逐一展示错误做法 + 为什么错]

正确做法（40 秒 - 结尾）：给出解决方案
[逐一展示正确做法 + 为什么对]
```

### 模板 3：故事弧线

适合叙事型内容：

```
开场：设定场景
"三个月前，我的 Newsletter 只有 47 个订阅者。"

冲突：遇到困难
"我每周花 8 小时写一篇，完全没有人看。"

转折：发现/改变
"然后我做了一件事——"

高潮：结果
"三个月后，订阅者涨到了 5000。"

教训：可带走的
"不是我写得更好了。/ 是我找到了正确的分发方法。"
```

### 模板 4：清单速递

适合信息密度型内容：

```
开场（3 秒）：
"五个我每天都在用的 AI 工具——"

主体：
"第一个：[名字]。/ 我用它来 [用途]。/ [一句话评价]。"
[重复 5 次]

结尾：
"如果只选一个——/ 我选第 [N] 个。/ 原因在评论区。"
```

## 8.3 口播节奏的微观技术

### 8.3.1 句长控制

- **黄金句长**：口播的最佳句长是 10-20 个字。
- **长句后必须接短句**：这是最基本的节奏感。

```
"AI 可以帮你在 30 分钟内生成一篇 2000 字的初稿。" (23 字)
"但初稿不是终稿。" (7 字)
"永远不是。" (4 字)
```

### 8.3.2 三的法则

人的大脑天然喜欢"三"这个数字。三个例子、三个步骤、三次重复——都比两个或四个更有节奏感。

```
"好内容有三个特征：/ 真实、/ 具体、/ 有观点。"
"第一，别让 AI 帮你做判断。/ 第二，别让 AI 帮你选立场。/ 第三——别让 AI 代替你思考。"
```

### 8.3.3 "说人话"检查法

写完脚本后，大声朗读一遍。标记以下问题：

| 问题 | 症状 | 解决 |
|------|------|------|
| 嘴巴打结 | 连续多个辅音、长定语 | 拆句、换词 |
| 听起来像论文 | "因此""综上""不可否认" | 换成"所以""总的来说""说实话" |
| 节奏单调 | 每句话差不多长 | 加入短句做强调 |
| 像在念稿 | 没有停顿标记、没有语气词 | 加 `[停顿]``[加重]` |
| 距离感 | 没有"你"字、都是第三人称 | 改成直接对观众说话 |

### 8.3.4 脚本标记系统

在脚本中使用统一的标记：

```
/          — 短停顿（0.3秒，换气）
//         — 长停顿（0.5-1秒，制造悬念或强调）
[加重]      — 这个词要重读
[轻]       — 这句降低音量，制造亲密感
[快]       — 加速，制造紧迫感
[慢]       — 减速，强调
[笑]       — 带笑意说
[画面切]    — 提醒剪辑在此处切画面
```

**示例**：

```
你有没有发现—— /
[慢] 你用 AI 写的东西， / 读起来总有一种…… // 说不出的 [加重] 假。 //

[快] 不是说内容不对， / 结构没问题， / 逻辑也说得通—— /

[慢] 但就是…… // 少了点什么。 //

[正常] 今天我告诉你少了什么。 / 以及怎么补回来。 //
```

## 8.4 AI 脚本生成的提示词要点

### 关键参数

让 AI 写脚本时，你需要明确以下信息：

```
请写一个视频脚本：

1. 平台：[YouTube / 抖音 / B站 / 小红书 / X]
   （这决定时长、语气、信息密度）

2. 时长：[X 分钟 / X 秒]

3. 类型：[口播 / 旁白配画面 / 对谈 / 教程演示]

4. 受众画像：[具体描述——年龄、身份、痛点、认知水平]

5. 核心论点：[一句话]

6. 结构模板：[HPAR / 问题-错误-正确 / 故事弧线 / 清单速递]

7. 语气参考：[粘贴你之前的一段脚本，或描述风格]

8. 输出格式：两栏脚本（左：画面描述 / 右：口播文字），包含停顿标记

9. 禁止：
   - 不要用"让我们""在当今""值得注意的是"
   - 不要用被动语态
   - 句子不超过 25 字
   - 每 30 秒必须有一次"你"
```

### 迭代技巧

第一版脚本通常不够好。用以下提示词迭代：

```
[口播感不足]
"请改写这个脚本，让它听起来像朋友之间的对话而不是演讲。加入口语化表达、停顿标记、和直接对观众说话的句子。"

[节奏单调]
"请改写，要求：连续 3 个长句后必须接一个短句（10 字以内）。在关键观点前加 1 秒停顿。"

[信息密度不够]
"请压缩，目标：在不丢核心信息的前提下，把时长减少 30%。删掉所有过渡句和废话。"

[太像 AI]
"请用更直接、更个人化的方式重写。加入 [你的经历/比喻/口头禅]。删掉所有'首先/其次/此外'。"
```

## 8.5 实践任务

1. **格式转换**：把你上周写的一篇 Newsletter（或 Thread），用 HPAR 结构改写成一个 90 秒视频脚本。
2. **朗读测试**：大声朗读脚本，标记所有"嘴巴打结"的地方——改。
3. **停顿标记**：给脚本加上完整的停顿标记（`/` 和 `//`）。
4. **节奏检查**：检查是否每 3 个长句后有一个短句。如果没有——改。
