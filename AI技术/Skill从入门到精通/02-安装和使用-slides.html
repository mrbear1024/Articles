Skill 从入门到精通 · 第二章

安装和使用 Skill

从安装到筛选到日常管理
帮你建立一套健康的 Skill 使用习惯

什么时候该用 Skill

Claude 生态里有好几种"让 Claude 记住你的偏好"的方式，先搞清楚它们的区别。

Skill
vs
Prompt
做一次用 Prompt，做三次以上用 Skill。反复输入同样的指令、反复上传同样的参考材料，就是在浪费时间。
Skill
vs
CLAUDE.md
CLAUDE.md 是全局规则，始终生效；Skill 是场景化的，只在特定任务触发时加载。所有对话都该遵守 → CLAUDE.md，做某类任务才需要 → Skill。
Skill
vs
Projects
Projects 有边界，只在特定项目里生效；Skill 跨越所有对话。只在一个项目中用 → Project，多个项目通用 → Skill。

三个信号告诉你该做 Skill 了

1 反复解释同一套做法
第三次向 Claude 解释的时候就该停下来，把它写成 Skill。
2 输出质量高度依赖特定参考材料
品牌规范、API 文档、行业模板——每次都要先上传这些材料，Skill 可以把它们打包在 references/ 目录里。
3 前置准备比执行本身还麻烦
先找文件、设参数、说规则，然后 Claude 才能开始干活。这种"仪式感"正是 Skill 要消除的。

安装 Skill 的三种方式

⌨
命令行安装
npx skills add author/repo
自动从 GitHub 拉取并放到正确位置。最常用的方式。
📁
手动安装
cp -r my-skill ~/.claude/skills/
直接复制目录。适合本地开发或从他人处拷贝的 Skill。
💬
对话安装
帮我从 jimliu/baoyu-skills 安装技能
直接对 Claude 说，它会引导完成。最直观的方式。

三种方式效果完全一样，最终都是把 Skill 目录放到 ~/.claude/skills/ 下

哪里找到高质量 Skill

渠道 地址 特点

评估第三方 Skill 的质量

安装前花 30 秒做一个快速评估：

  1. 读 description —— 是否清晰、具体、包含明确的触发词？模糊的 description 意味着会乱触发或不触发。
  2. 看文件结构 —— 是否有 SKILL.md、scripts、references 的合理分层？只有一个光秃秃的 SKILL.md，通常功能有限。
  3. 试一次 —— 安装后用一个真实任务测试。能顺利跑通才算合格。
  4. 查看 scripts/ —— 脚本会被 Claude 直接执行。确保里面没有可疑操作（删除文件、上传到未知服务器）。

Skill 的三种类型

能力型
提供底层能力
封装 Python 库和模板脚本，提供你自己写要花一整天的能力。
pdf xlsx docx pptx
选择标准：工作涉及就值得装，触发清晰，几乎不误触发
参考型
包含领域知识
高质量参考文档，相当于在 Claude 身边放一本筛选过的参考书。
claude-api brand-guidelines skill-creator
选择标准：几乎不污染触发空间，装了就忘，用到就受益
流程型
封装工作流程
沉淀特定的工作流程，按作者习惯设计——排版偏好、发布流程、风格标准。
wechat-publisher tweet-writer
选择标准：流程型 Skill 应该自己写，装别人的是穿别人的鞋

安装数量的上限

Skill 靠 description 中的关键词自动激活。装太多会导致触发词污染——Claude 触发错误的 Skill 比不触发更糟糕。

10-15

建议的 Skill 总数上限

超过 20-30 个，体验开始明显下滑

4 个  文件能力型
pdf、xlsx、docx、pptx
3 个  参考资料型
claude-api、skill-creator、brand-guidelines
2 个  外部服务连接型
根据你实际使用的服务选
3 个  专业领域工具型
根据你的职业选
+ N  自己沉淀的流程型 Skill

装之前的三个自检问题

1
过去一个月，做过三次以上这个任务吗？
没有就别装。一个月做不到三次，Skill 放在那里只会占触发空间。
2
触发词会不会和现有 Skill 撞车？
看 description 的触发关键词，和你已有的 Skill 有重叠就是定时炸弹。
3
自己一天能写出来吗？
如果能，建议自己写。自己写的 Skill 完全契合你的习惯，你能随时改。

通过的就装，没通过的果断放过。

建议的起步清单

新手不想花时间筛选，从这套最小集合开始：

分类Skill装它的理由
文件能力 pdf、xlsx、docx、pptx 办公场景通用，触发清晰
参考资料 claude-api、skill-creator 静态知识，长期有效
外部服务 按你用的服务挑 1-2 个 仅装真在用的
专业能力 按你的领域挑 1-2 个 前端选 webapp-testing，内容选 ffmpeg
先用这套最小集合跑一个月。一个月后你自然会知道哪些 Skill 真正在帮你省时间。

日常使用：触发方式

斜杠触发 — 百分之百精准

/weekly-report 本周完成了用户系统重构
和支付接口联调，下周计划做灰度发布

脑子里浮现了 Skill 名称 → 用斜杠
带参数一步到位，省去追问环节

自然语言 — 让 Claude 判断

帮我把这周做的事情整理一下，
生成一份周报

想的是"要完成某件事" → 用自然语言
Claude 根据 description 自动匹配

经验法则：明确任务用斜杠，模糊需求用自然语言。给 Skill 的上下文越充分，输出质量越高。

控制 Skill 的触发行为

disable-model-invocation

设为 true 后，只能通过斜杠手动触发。
适合部署、发布、推送等有副作用的操作。

---
name: deploy
description: 部署应用到生产环境
disable-model-invocation: true
---

user-invocable

设为 false 后，不出现在 / 菜单里。
适合背景知识型参考 Skill。

---
name: legacy-system-context
description: 旧系统架构说明
user-invocable: false
---
配置你能触发Claude 能触发
默认YesYes
disable-model-invocation: trueYesNo
user-invocable: falseNoYes

使用中的常见问题

Skill 没有触发
表述和触发词不匹配 → 用 / 直接调用验证
YAML 格式有语法错误 → 检查 --- 分隔符和缩进
执行结果不理想
输入信息不够 → 触发时一并给出关键信息
流程定义有缺陷 → 修改 SKILL.md 补上规则
多个 Skill 冲突
短期 → 用斜杠精确触发
长期 → 减少数量，修改 description 排除条件
触发了错误的 Skill
直接说"不对，我要的是 yyy，请用 yyy 重新来"
不需要开新对话，Claude 会立刻切换
调试技巧：直接问 Claude "你刚才用了哪个 Skill？为什么选它？" — Claude 会解释触发逻辑。
核心原则
装别人的能力型 Skill 是买工具
装别人的流程型 Skill 是穿别人的鞋

能力型和参考型可以装别人的
流程型应该自己写

本章小结

  • 判断时机 — 反复解释的做法、依赖参考材料的任务、仪式感过重的工作，都该做 Skill
  • 发现渠道 — 优先 Claude Code 内置 + Anthropic 官方仓库，再看 agentskills.io 和 GitHub 社区
  • 区分类型 — 能力型和参考型装别人的，流程型自己写
  • 控制数量 — 10-15 个以内，每月清理一次
  • 高效使用 — 明确任务用斜杠，模糊需求用自然语言，给足上下文
  • 精细控制 — 有副作用的操作用 disable-model-invocation 防止自动触发
