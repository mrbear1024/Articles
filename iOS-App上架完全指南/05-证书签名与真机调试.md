# 05 证书、签名与真机调试

如果统计「iOS 新手在哪一步弃坑」，证书签名大概率排第一。Stack Overflow 上关于 code signing 的提问超过十万条，报错信息一个比一个不像人话：「No signing certificate found」「Provisioning profile doesn't include the currently selected device」。

但这件事的本质其实很简单，而且 2019 年之后 Xcode 的自动签名已经把绝大部分手工操作收编了。**这一章的目标：让你理解这套体系在干什么，然后用自动签名把它一键解决，再把可能的报错逐个排掉。**

---

## 一、签名体系在解决什么问题

苹果对 iOS 的核心承诺是：设备上跑的每一个 App，都能追溯到一个签了协议的真实开发者。一旦发现恶意行为，吊销这个开发者的证书，他的所有 App 立刻全网失效。

为了兑现这个承诺，苹果设计了三件套：

| 组件 | 是什么 | 类比 |
|------|------|------|
| 证书（Certificate） | 证明「你是你」的加密文件，存在你的 Mac 钥匙串里 | 你的身份证 |
| App ID（Bundle ID） | App 的全球唯一标识，如 com.wanghe.DayCount | 房子的门牌号 |
| 描述文件（Provisioning Profile） | 把「谁 + 哪个 App + 哪些设备 + 哪些权限」绑在一起的授权书 | 写明人、房、期限的房产证 |

签名（Code Signing）就是用你的证书给 App 盖章。iPhone 安装 App 时会验章：证书有效吗？描述文件里包含这台设备吗？Bundle ID 对得上吗？三问全过才允许运行。

证书还分两类，用途不同：

- **开发证书（Apple Development）**：日常调试用，配合的描述文件里要列明设备清单
- **发布证书（Apple Distribution）**：打包上传 App Store 用，不限设备——因为分发由苹果接管

你不需要手动创建它们中的任何一个。理解到这一层就够了，下面交给 Xcode。

## 二、打开自动签名：两步配置

打开上一章的 DayCount 项目，点导航区顶部的项目图标，选中 TARGETS 下的 DayCount，切到 **Signing & Capabilities** 标签：

**第一步，勾选「Automatically manage signing」。** 默认就是勾上的，确认它在。

**第二步，在 Team 下拉框里选择你的开发者团队。** 如果下拉框是空的，先去 Xcode → Settings → Accounts，点左下角 +，登录你的开发者 Apple ID。登录后回来，选中显示为「你的名字 (Personal Team 或 Individual)」的那一项——注意，如果同时出现「Personal Team」和不带后缀的团队，**选不带「Personal Team」的那个**，Personal Team 是免费账号的七天临时签名。

选完之后，看到 Signing 区域显示「Signing Certificate: Apple Development」且没有红色报错，就成了。这两步背后，Xcode 自动帮你做了四件事：生成开发证书、注册 Bundle ID、注册你的设备、生成并下载描述文件。十年前这是四个网页表单加一次钥匙串导入，现在是两次点击。

## 三、把 App 装进真 iPhone

**第一步，连接设备。** 用数据线把 iPhone 连上 Mac（第一次必须有线，之后可以无线调试）。iPhone 上弹出「信任此电脑？」，点信任。

**第二步，打开开发者模式。** iOS 16 起，真机调试需要手动开启开发者模式：iPhone 上进「设置 → 隐私与安全性 → 开发者模式」，打开，重启手机。如果设置里找不到这个开关，先让 Xcode 连一次设备它就会出现。

**第三步，选中设备并运行。** Xcode 顶部工具栏的运行目标里，你的 iPhone 会出现在模拟器列表上方。选中它，⌘R。第一次会比较久，Xcode 要向这台设备部署调试支持文件。

**第四步，信任开发者。** 第一次运行会失败，iPhone 提示「不受信任的开发者」。去 iPhone 的「设置 → 通用 → VPN 与设备管理」，找到你的开发者证书，点信任。回 Xcode 再 ⌘R。

你的 App 出现在 iPhone 桌面上了。**把它拿在手里点一点——模拟器里再流畅的东西，握在手里的感觉都是另一回事。** 顺手检查：字够不够大、按钮顺不顺手、深色模式下对不对劲。

## 四、报错排查表

签名报错看着吓人，常见的就这么几种：

| 报错关键词 | 原因 | 解法 |
|------|------|------|
| Failed to register bundle identifier | Bundle ID 被别人占了（全球唯一） | 改一个，如 com.你的ID.daycount2026 |
| No account / No profiles for team | Xcode 没登录开发者账号 | Settings → Accounts 登录后重选 Team |
| Untrusted Developer | 没在手机上信任证书 | 设置 → 通用 → VPN 与设备管理 → 信任 |
| Developer Mode disabled | 没开开发者模式 | 设置 → 隐私与安全性 → 开发者模式 |
| Device not eligible / OS 版本不匹配 | 手机系统比 Xcode 支持的新或太旧 | 升级 Xcode，或调低 Minimum Deployments |
| Communication with Apple failed | 网络问题，国内常见 | 换网络重试，或挂代理 |
| Revoke certificate 弹窗 | 换了新 Mac，旧证书私钥不在这台机器上 | 点 Revoke 让 Xcode 重新生成，对已上架 App 无影响 |

补充两条经验：

**遇到玄学问题，先做「签名三连」：** 清理构建（⌘⇧K）、删掉手机上的旧 App、重启 Xcode。能解决一半的疑难杂症。

**「Revoke 证书会不会影响线上 App」是新手最常见的恐慌。** 答案：开发证书随便吊销重建，毫无影响；发布证书吊销也不影响已上架的 App（App Store 的分发签名由苹果完成），只影响你重新打包。放心点那个按钮。

## 五、留给下一阶段的两个概念

有两个词你很快会在别处遇到，提前打个照面：

- **Archive（归档）**：把 App 用发布证书打成正式包的动作，在第六章上传构建版本时会用到。入口在 Xcode 菜单 Product → Archive
- **Capabilities（能力）**：Signing & Capabilities 页左上角的「+ Capability」，用来给 App 申请特殊权限（推送、iCloud、Apple 登录等）。我们的倒数日 App 一个都不需要——又一次体现了「第一个 App 做纯本地工具」的好处

## 写在最后

签名体系是苹果生态里「安全」与「麻烦」的交换合同：开发者多走流程，用户少中木马。理解了三件套的逻辑，那些报错就从天书变成了填空题——缺哪样，补哪样。
