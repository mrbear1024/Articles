# 01 全景图：从想法到上架，你要经过什么

2008 年 App Store 刚开张的时候，整个商店只有 500 个 App。今天，每周仍有上万个新 App 提交审核，其中大约四成会在第一次提交时被拒。

被拒的原因五花八门，但背后往往是同一件事：开发者直到提交前一天，才第一次了解上架流程。证书没配对、隐私政策链接是空的、截图尺寸不对、内购没走苹果支付——这些坑没有一个跟「代码写得好不好」有关。

所以这份指南的第一章不讲代码，先给你一张完整的地图。**看清全程再出发的人，比边走边问路的人快得多。**

---

## 一、完整流程：七个站点

从零到上架，你会依次经过这七个站点：

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│ ① 开发者账号 │──▶│ ② 开发环境   │──▶│ ③ 写出 App  │
│  $99/年     │   │  Mac + Xcode│   │  SwiftUI    │
└─────────────┘   └─────────────┘   └─────────────┘
                                          │
┌─────────────┐   ┌─────────────┐   ┌─────▼───────┐
│ ⑥ 上架材料   │◀──│ ⑤ TestFlight│◀──│ ④ 证书签名  │
│ 图标/截图/隐私│   │  内测      │   │  真机调试    │
└─────┬───────┘   └─────────────┘   └─────────────┘
      │
┌─────▼───────┐
│ ⑦ 提交审核   │──▶ 🎉 上架 App Store
│  1~2 天     │
└─────────────┘
```

每个站点对应本指南的一章。其中两个站点值得提前预警：

**④ 证书签名是技术上最容易卡住的地方。** 苹果用一套「证书 + 标识符 + 描述文件」的体系来保证每个 App 都能追溯到一个真实的开发者。好消息是 Xcode 的自动签名已经能处理 90% 的情况，第五章会讲清楚剩下的 10%。

**⑦ 审核是心态上最容易崩溃的地方。** 审核员是真人，标准有弹性，被拒是常态而非意外。第九章会列出最高频的被拒条款和应对方法。

## 二、成本账：要花多少钱

很多人以为做 App 很贵。把账摊开算，必选项其实只有两笔：

| 项目 | 费用 | 必需吗 |
|------|------|--------|
| Apple Developer Program | 99 美元/年（约 688 元） | 必需，不交钱无法上架 |
| 一台能跑 Xcode 的 Mac | 二手 M1 Mac mini 约 2000 元起 | 必需，Windows 没有替代方案 |
| iPhone 真机 | 你手上的旧 iPhone 即可 | 强烈建议，模拟器测不出全部问题 |
| 域名 + 隐私政策页面 | 0 元（GitHub Pages 免费托管） | 隐私政策必需，但不用花钱 |
| 图标与截图设计 | 0 元（Figma 免费版自己做） | 必需，但可以零成本 |
| App 后端服务器 | 0 元起 | 看 App 类型，纯本地工具不需要 |

**最低启动成本：一台 Mac 加 99 美元年费。** 如果你已经有 Mac 和 iPhone，从今天到上架，现金支出就是那 99 美元。

注意一个常见误解：99 美元是年费，不续费的话 App 会被下架。把它当成「摊位租金」而非一次性门票。

## 三、时间账：要花多久

假设你每天能投入两三个小时，一个真实的时间线大概是这样：

| 阶段 | 耗时 | 说明 |
|------|------|------|
| 注册开发者账号 | 1~3 天 | 付款后审核通常 48 小时内 |
| 搭环境 + 学 SwiftUI 基础 | 3~7 天 | 有编程基础的话一周足够入门 |
| 开发一个小工具 App | 1~4 周 | 取决于你对功能的克制程度 |
| 证书签名 + 真机调试 | 半天~2 天 | 顺利半天，踩坑两天 |
| App Store Connect 配置 + 材料 | 1~2 天 | 截图和文案比想象中花时间 |
| TestFlight 内测 | 3~7 天 | 可以压缩，但别跳过 |
| 提交审核到上架 | 1~3 天 | 90% 的 App 在 48 小时内出结果 |

加起来，**一个有编程基础的人，从零开始到 App 上架，现实的预期是四到八周。** 网上「三天上架一个 App」的说法也是真的——前提是 App 本身极简单，而且你已经走通过一次全流程。

## 四、三个最重要的提前决策

有三件事，在写第一行代码之前想清楚，能帮你省掉后面大量的返工。

**第一，做什么。** 第一个 App，强烈建议做一个「纯本地的小工具」：计算器变体、习惯打卡、单位换算、倒数日、白噪音播放器。原因很直接——不需要服务器、不需要账号系统、不需要处理用户数据，每少一项，审核风险和开发量都砍掉一截。把你的宏大想法留给第二个 App。

**第二，免费还是收费。** 第一个 App 建议直接免费，不带内购。一旦涉及收费，审核会多查一层（条款 3.1.1），你也要多配置银行账户、税务表单这些环节。先走通流程，变现是第十章的事。

**第三，要不要上中国区。** 2023 年起，App 在中国大陆区上架需要 ICP 备案，个人开发者办理备案需要满足一系列条件。很多独立开发者的选择是首发时去掉中国大陆区，先上其他 174 个区。这个决策的完整分析在第十一章，现在你只需要知道：这是一个选项，不是死路。

## 五、你和上架之间，隔着一份清单

把全程压缩成一份检查清单，后面每一章就是在逐项打勾：

- [ ] 一个付费的 Apple Developer 账号（第二章）
- [ ] 装好 Xcode 的 Mac（第三章）
- [ ] 一个能在模拟器里跑起来的 App（第四章）
- [ ] 能在真机上运行（第五章）
- [ ] App Store Connect 里建好了 App 条目（第六章）
- [ ] TestFlight 里有人测过（第七章）
- [ ] 图标、截图、描述、隐私政策、隐私标签齐全（第八章）
- [ ] 点下「提交审核」按钮（第九章）

## 写在最后

上架一个 App 的本质，是和苹果这个全世界最挑剔的平台方做一次完整的交易：你交付一个符合它规则的产品，它给你触达十几亿台设备的分发渠道。

规则很多，但都是明牌。下一章，我们从那个 99 美元的账号开始。
