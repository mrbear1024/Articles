# 03 准备开发环境

iOS 开发环境的清单短得出奇：一台 Mac，一个 Xcode，结束。没有 Node 全家桶，没有环境变量地狱，不用配 JDK。

但这份清单也强硬得出奇：**Mac 是必需的，没有任何官方替代方案。** Windows 加虚拟机、云 Mac、Flutter 在 Windows 上开发——这些路线要么违反苹果许可协议，要么最后一步（签名和上传）依然绕不开一台真 Mac。如果你还没有 Mac，这一章先帮你用最少的钱解决它。

---

## 一、Mac 怎么选：够用就行

跑 Xcode 的硬性门槛是 Apple Silicon（M 系列芯片）或较新的 Intel 机型，加上较新的 macOS。实际体验上，给三条简单的建议：

| 预算 | 方案 | 说明 |
|------|------|------|
| 2000 元左右 | 二手 M1 Mac mini（16GB 内存） | 性价比之王，跑 Xcode 完全流畅 |
| 5000 元左右 | M4 Mac mini 新机 | 全新、保修、性能富余 |
| 已有 Mac | 8GB 内存也能用 | 模拟器会吃内存，关掉别的应用就行 |

两条经验之谈：**内存优先于芯片代际**——Xcode 加模拟器轻松吃掉 10GB，16GB 内存的 M1 体验好于 8GB 的 M3。**硬盘留足 60GB 空闲**——Xcode 本体加模拟器运行时占 25~40GB，再算上项目缓存，少于 60GB 你会反复清磁盘。

显示器、键盘、鼠标都不挑，Mac mini 接上你现有的外设就能开工。

## 二、安装 Xcode

Xcode 是苹果官方的集成开发环境，写代码、跑模拟器、签名、打包、上传，全在里面。安装有两条路：

**路线 A：Mac App Store（推荐新手）。** 打开 Mac 上的 App Store，搜「Xcode」，点安装。优点是后续自动更新，缺点是下载经常很慢且没有进度细节。

**路线 B：开发者官网手动下载。** 去 [developer.apple.com/download](https://developer.apple.com/download/applications/)，登录开发者账号，下载 Xcode 的 .xip 文件。优点是可以用下载工具续传、可以装多版本，独立开发者用熟之后多半切到这条路线。

不管哪条路线，安装包十几个 GB，第一次下载请直接安排在睡前。

装完第一次启动时，Xcode 会要求安装额外组件（Command Line Tools 和 iOS 模拟器运行时），全部同意。模拟器运行时本身又是几个 GB，同样需要耐心。

验证安装是否成功：打开终端，输入 `xcodebuild -version`，能打印出 Xcode 版本号就说明一切就绪。

一个和上架直接相关的注意点：**苹果每年都会要求新提交的 App 用最新大版本的 SDK 构建**（通常在每年 4 月生效）。所以不要为了「稳定」固守旧版 Xcode，保持 Xcode 是当前最新的正式版即可——正式版，不是 beta 版，beta 版构建的包无法提交 App Store。

## 三、五分钟认识 Xcode

打开 Xcode，选「Create New Project → iOS → App」，随便起个名字，就能看到主界面。你最常用的是四个区域：

```
┌──────────┬──────────────────────┬──────────┐
│          │                      │          │
│  导航区   │      代码编辑器        │  检查器   │
│ （左栏）  │                      │ （右栏）  │
│ 文件树    │   ┌──────────────┐   │ 属性面板  │
│ 搜索      │   │   实时预览     │   │          │
│ 报错列表  │   │  （Canvas）   │   │          │
│          │   └──────────────┘   │          │
├──────────┴──────────────────────┴──────────┤
│  调试区（底部）：控制台输出、变量查看            │
└─────────────────────────────────────────────┘
```

- **导航区**（⌘1~⌘9 切换）：文件树在这里，报错也在这里
- **编辑器与实时预览**：写 SwiftUI 时，右侧 Canvas 会实时渲染界面，改一行代码立刻看到效果，这是 SwiftUI 开发体验的核心
- **顶部工具栏**：选择运行目标（某个模拟器或你的真机），点左侧的 ▶ 运行
- **调试区**：`print()` 的输出和崩溃信息都在这里看

记住两个快捷键就能开工：**⌘R 运行，⌘.（Command+句号）停止。**

## 四、跑通模拟器：你的第一次 ⌘R

在顶部工具栏把运行目标选成任意一台 iPhone 模拟器，按 ⌘R。第一次构建会慢一些，之后屏幕上会弹出一台虚拟 iPhone，运行着你刚创建的空白 App——通常是一个地球图标加一行「Hello, world!」。

模拟器能完成 80% 的日常开发调试，几个常用操作：

- ⌘← / ⌘→ 旋转设备，⌘⇧H 回到主屏幕
- File → Open Simulator 可以同时开多台不同尺寸的设备
- 拖一张图片进模拟器窗口，就能存进虚拟相册——测图片选择功能时很有用

模拟器测不了的东西也要心里有数：推送通知的真实送达、相机、NFC、性能表现。这些留给第五章的真机调试。

## 五、两个值得顺手装上的免费工具

**SF Symbols。** 苹果官方的图标库 App，内含六千多个与系统风格一致的矢量图标，代码里一行 `Image(systemName: "heart.fill")` 就能用。在 [developer.apple.com/sf-symbols](https://developer.apple.com/sf-symbols/) 下载。你的 App 里 90% 的图标需求它都能解决，而且零版权风险。

**AI 编程助手。** 这个时代学 iOS 开发，AI 是合法外挂。Xcode 自带代码补全模型，而 Claude Code、Cursor 这类工具可以直接读写你的项目文件。给新手的用法建议：让 AI 写第一版，但每一行都要自己读懂——上架路上的报错千奇百怪，读不懂代码的人会在第一个报错处搁浅。

## 写在最后

环境搭建是整条链路里最枯燥但最确定的一段：照做就能成，没有玄学。当你按下 ⌘R、看到模拟器里亮起「Hello, world!」的那一刻，环境问题就永久地翻篇了。
